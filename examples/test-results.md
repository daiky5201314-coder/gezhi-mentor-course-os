## Test 1｜重新设计院校篇

**模拟路由**

体系设计 → 读取项目上下文、八篇60课、院校篇知识点及跨篇关系 → 检查每课唯一能力和知识点归属 → 输出篇章设计方案 → Checkpoint 1。

**阻断检查**

- 不允许直接进入逐页稿。
- 不允许只读院校篇而忽略专业篇、测评篇、实操篇。
- 修改主讲归属必须显式说明并同步164映射。

**结果：通过。**

## Test 2｜设计院校篇第06课

**识别结果**

- 课程：第06课《真正看懂一所大学：格知院校六维评价模型》
- 唯一主讲：YX-05 学科实力评价、YX-06 人才培养与升学、YX-07 就业质量与社会认可、YX-08 排名正确使用、YX-09 院校研究标准框架
- 前课：第05课已解决院校身份识别
- 后课：第07课主讲城市、校区与培养机制；第08课主讲学校—专业—城市权衡
- 应用课：第09—12课调用六维模型研究云南和省外院校

**边界判定**

- 必须讲：六维模型、指标证据、研究顺序和宣传核验；《格知院校研究模板》是课表产出字段，不自动变成独立工具页。
- 可以引用：第05课院校身份；不重新定义本科、公民办、双一流、原985/211。
- 禁止展开：第07课城市校区机制、第08课具体权衡、第09—12课具体院校结论。
- 停止点：输出课程设计方案后停在Checkpoint 1。

**结果：通过。**

## Test 3｜“太理论了”

**模拟诊断**

系统不会只增加口语化表达，而会检查：

- 是否缺少真实或明确标注的合成案例
- 是否缺少招聘、毕业去向、学历门槛等现实证据
- 是否缺少普通学生和云南家庭场景
- 是否缺少导师在本课对应服务问题中可直接使用的判断、提问和风险提醒；不默认增加独立工具
- 新增就业内容是否符合本课边界

修改范围以相关模块为主，不重写无关内容。

**结果：通过。**

## Test 4｜生成逐页PPT内容稿

**前置状态**

完整课程内容蓝图已确认；若用户明确授权同一轮完成，则内部仍完成蓝图与审核。

**页面完成标准**

每页至少具有：

- 页码
- 教学型标题
- 本页核心观点
- 可直接上屏的完整正文
- 页面表达建议

案例/数据、讲解重点、来源与核验按页面需要出现。禁止“此处加案例”等占位语；不固定页数；不生成PPTX；不默认写逐字稿。

**结果：通过。**

## Test 5｜“第12页太普通，换掉”

**模拟路由**

1. 识别第12页承担的教学任务。
2. 检查与第11、13页的叙事关系。
3. 诊断是常识、重复、缺证据、缺判断还是没有推进。
4. 选择删除、合并或替换。
5. 输出完整的新第12页。
6. 更新受影响的页码、转场、交叉引用和来源。
7. 只修改必要范围。

**结果：通过。**

## 尚未覆盖

- 未用一门真实新课程跑完两次Checkpoint和完整逐页交付，因此动态研究深度、真实案例质量和最终页数仍需在第一次实战中验证。
- 未接入格知完整学生画像、测评报告、审核表、方案表和咨询案例库，相关工具只能先按已有资料设计接口。

## Test 6｜课表产出不自动上屏（2026-09-22增补）

以院校篇第05课为反例检查：课表“课程产出”为《高校身份识别框架》，但这不是制作“五件套工具页”或“10分钟SOP”的授权。新规则要求页面只从核心问题、核心内容、去重职责和已确认蓝图推导；独立迁移页、总结页和上屏来源表均不得自动追加。来源仍在非上屏备注中保留可追溯性。

**结果：规则核验通过。** 这一项尚未通过真实完整逐页稿检验，首次产出院校篇第05课时仍需复测。

## Test 7｜规划师能力而非额外产出（2026-09-22增补）

核对主Skill、课程架构、项目上下文与质量审核：单课能力必须对应课表范围内的具体规划师服务问题；业务场景决定案例、证据和讲授深度，不授权扩展到完整咨询流程或额外工具。

**结果：规则核验通过。** 尚未以真实单课完整研发过程验证行为。
